# 모델 디바이스 선택

SelectModelDevice 노드는 확산 모델이 실행될 장치(CPU 또는 특정 GPU)를 선택할 수 있게 합니다. 선택한 옵션에 따라 로더의 원래 장치를 복원하거나, 모델을 CPU에 고정하거나, 특정 GPU로 이동하며, 다른 멀티 GPU 노드와의 충돌을 자동으로 처리합니다.

## 입력

| 매개변수 | 설명 | 데이터 타입 | 필수 | 범위 |
| --- | --- | --- | --- | --- |
| `model` | 특정 장치에 배치할 확산 모델입니다. | MODEL | 예 |  |
| `device` | 모델의 대상 장치입니다. 옵션은 사용 가능한 GPU를 기반으로 동적으로 생성됩니다. (기본값: "default") | COMBO | 예 | `"default"`<br>`"cpu"`<br>각 사용 가능한 GPU에 대한 `"gpu:N"` (예: `"gpu:0"`, `"gpu:1"`, ...) |

**매개변수 세부 정보:**
- `"default"`: 이전 SelectModelDevice 노드가 장치를 변경했더라도 모델 로더가 할당한 장치를 복원합니다.
- `"cpu"`: 로드 및 오프로드 장치를 모두 CPU에 고정합니다.
- `"gpu:N"`: 로드 장치를 N번째 사용 가능한 GPU에 고정합니다(예: 첫 번째 GPU의 경우 `"gpu:0"`). 오프로드 장치는 로더의 원래 선택으로 복원됩니다.

**중요 참고 사항:**
- 알 수 없는 `"gpu:N"` 값은 검증 시간에 허용되므로 GPU가 더 적은 머신에서도 이식 가능한 워크플로우가 실패하지 않습니다. 런타임에 사용할 수 없는 장치가 있으면 모델을 변경하지 않고 통과시키고 로그 메시지를 출력합니다.
- 요청된 장치가 현재 머신에 없는 경우(예: 2-GPU 머신에서 만든 워크플로우를 1-GPU 머신에서 여는 경우), 노드는 실패하는 대신 모델을 변경하지 않고 통과시키고 로그 메시지를 출력합니다.
- 모델이 이미 요청된 장치에 있는 경우, 노드는 빠른 경로를 사용하며 모델을 다시 로드하지 않습니다.
- 요청된 장치가 현재 장치와 다른 경우, 로더의 리로드 팩토리를 사용하여 새 모델이 생성되므로 반환된 모델은 새 장치에서 독립적인 가중치를 갖습니다. 이를 지원하지 않는 로더는 노드가 경고와 함께 모델을 변경하지 않고 통과시키게 합니다.
- 워크플로우에 이미 MultiGPU CFG Split이 적용되어 있고 선택한 GPU가 기존 멀티 GPU 클론 중 하나와 일치하는 경우, 두 패처가 동일한 장치에 바인딩되지 않도록 해당 클론이 제거됩니다.
- 이미 모델을 소비한 노드(예: KSampler) *뒤에* 이 노드를 배치하는 것은 권장되지 않습니다. 장치가 원래와 일치하면 이전 노드에 의해 변경된 상태가 관찰될 수 있기 때문입니다.

## 출력

| 출력 이름 | 설명 | 데이터 타입 |
| --- | --- | --- |
| `model` | 선택한 장치에 배치된 확산 모델입니다. 장치가 잘못되었거나 사용할 수 없는 경우 모델이 변경되지 않은 채 통과됩니다. | MODEL |
