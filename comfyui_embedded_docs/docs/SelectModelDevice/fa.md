# انتخاب دستگاه مدل

گره Select Model Device به شما امکان می‌دهد دستگاه مورد نظر (CPU یا یک GPU مشخص) را برای اجرای مدل دیفیوژن به‌صورت دستی انتخاب کنید. این گره می‌تواند یک مدل را به دستگاه دیگری منتقل کند و تعارض‌ها با سایر گره‌های چند-GPU را به‌صورت خودکار مدیریت می‌کند. انتخاب `"default"` دستگاه اصلی انتخاب‌شده توسط بارگذار مدل را بازمی‌گرداند.

## ورودی‌ها

| پارامتر | توضیحات | نوع داده | الزامی | محدوده |
| --- | --- | --- | --- | --- |
| `model` | مدل دیفیوژنی که باید روی یک دستگاه مشخص قرار گیرد. | MODEL | بله |  |
| `device` | دستگاه هدف برای مدل. گزینه‌ها به‌صورت پویا بر اساس دستگاه‌های موجود در ماشین فعلی تولید می‌شوند. (پیش‌فرض: `"default"`) | COMBO | بله | `"default"`<br>`"cpu"`<br>`"gpu:0"`<br>`"gpu:1"`<br>... (یک ورودی `"gpu:N"` برای هر GPU شناسایی‌شده) |

**جزئیات پارامترها:**
- `"default"`: دستگاه‌های بارگذاری (load) و تخلیه (offload) تخصیص‌داده‌شده توسط بارگذار مدل را بازمی‌گرداند، حتی پس از فراخوانی قبلی Select Model Device.
- `"cpu"`: هم دستگاه بارگذاری و هم دستگاه تخلیه را به CPU پین می‌کند.
- `"gpu:N"`: دستگاه بارگذاری را به Nاُمین GPU موجود پین می‌کند (برای مثال، `"gpu:0"` برای اولین GPU). دستگاه تخلیه به انتخاب اصلی بارگذار بازگردانده می‌شود.

**نکات مهم:**
- اگر دستگاه درخواستی روی ماشین فعلی وجود نداشته باشد (برای مثال، یک گردش‌کار ساخته‌شده روی ماشین ۲-GPU روی ماشین ۱-GPU باز شود)، گره مدل را بدون تغییر عبور می‌دهد و به‌جای خطا دادن، یک پیام در لاگ ثبت می‌کند. مقادیر ناشناخته `gpu:N` در هنگام اعتبارسنجی ورودی مجاز هستند تا گردش‌کارهای قابل‌حمل زودتر خطا ندهند.
- اگر مدل از قبل روی دستگاه درخواستی باشد، گره از یک مسیر سریع استفاده می‌کند و مدل را دوباره بارگذاری نمی‌کند.
- وقتی دستگاه درخواستی با دستگاهی که مدل ورودی از قبل روی آن است متفاوت باشد، یک مدل تازه با استفاده از کارخانه بارگذاری مجدد (reload factory) بارگذار ایجاد می‌شود تا patcher جدید وزن‌های مستقلی روی دستگاه جدید داشته باشد.
- اگر بارگذار مدل از چند-GPU پشتیبانی نکند (بدون reload factory)، گره مدل را بدون تغییر عبور می‌دهد و یک هشدار در لاگ ثبت می‌کند.
- وقتی یک کلون MultiGPU CFG Split از قبل دستگاه انتخاب‌شده را اشغال کرده باشد، آن کلون حذف می‌شود تا دو مدل به یک دستگاه واحد متصل نشوند.
- وقتی یک دستگاه غیر پیش‌فرض (CPU یا GPU) انتخاب می‌شود، گره همچنین نوع داده محاسباتی (compute dtype) مدل را به یکی از انواع پشتیبانی‌شده توسط آن دستگاه تنظیم می‌کند.
- قرار دادن این گره بعد از گره‌ای که از قبل مدل را مصرف کرده است (برای مثال، یک KSampler) توصیه نمی‌شود، زیرا اگر دستگاه با دستگاه اصلی مطابقت داشته باشد، هر وضعیتی که گره قبلی تغییر داده باشد مشاهده خواهد شد.
