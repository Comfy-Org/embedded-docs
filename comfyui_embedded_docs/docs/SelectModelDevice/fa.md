# انتخاب دستگاه مدل

گره SelectModelDevice به شما امکان می‌دهد انتخاب کنید که یک مدل دیفیوژن روی کدام دستگاه (CPU یا یک GPU خاص) اجرا شود. بسته به گزینه انتخاب‌شده، دستگاه اصلی لودر را بازیابی می‌کند، مدل را به CPU پین می‌کند، یا آن را به یک GPU خاص منتقل می‌کند، و به‌طور خودکار تداخل‌ها با سایر گره‌های چند-GPU را مدیریت می‌کند.

## ورودی‌ها

| پارامتر | توضیحات | نوع داده | الزامی | بازه |
| --- | --- | --- | --- | --- |
| `model` | مدل دیفیوژن برای قرارگیری روی دستگاه خاص. | MODEL | بله |  |
| `device` | دستگاه هدف برای مدل. گزینه‌ها به‌صورت پویا بر اساس GPUهای موجود تولید می‌شوند. (پیش‌فرض: "default") | COMBO | بله | `"default"`<br>`"cpu"`<br>`"gpu:N"` برای هر GPU موجود (مثلاً `"gpu:0"`, `"gpu:1"`, ...) |

**جزئیات پارامتر:**
- `"default"`: دستگاهی را که توسط لودر مدل تعیین شده است بازیابی می‌کند، حتی اگر یک گره SelectModelDevice قبلی آن را تغییر داده باشد.
- `"cpu"`: هر دو دستگاه بارگذاری و تخلیه را به CPU پین می‌کند.
- `"gpu:N"`: دستگاه بارگذاری را به N-امین GPU موجود پین می‌کند (مثلاً `"gpu:0"` برای اولین GPU). دستگاه تخلیه به انتخاب اصلی لودر بازگردانده می‌شود.

**نکات مهم:**
- مقادیر ناشناخته `"gpu:N"` در زمان اعتبارسنجی پذیرفته می‌شوند تا گردش‌کارهای قابل‌حمل روی ماشین‌هایی با GPU کمتر دچار خطا نشوند. در زمان اجرا، اگر دستگاهی در دسترس نباشد، مدل بدون تغییر عبور داده می‌شود و یک پیام لاگ ثبت می‌شود.
- اگر دستگاه درخواستی روی ماشین فعلی وجود نداشته باشد (مثلاً گردش‌کاری که روی ماشین ۲-GPU ساخته شده روی ماشین ۱-GPU باز شود)، گره مدل را بدون تغییر عبور می‌دهد و به‌جای خطا دادن، یک پیام لاگ ثبت می‌کند.
- اگر مدل از قبل روی دستگاه درخواستی باشد، گره از مسیر سریع استفاده کرده و مدل را دوباره بارگذاری نمی‌کند.
- هنگامی که دستگاه درخواستی با دستگاه فعلی متفاوت باشد، با استفاده از کارخانه بازبارگذاری (reload factory) لودر، یک مدل تازه ایجاد می‌شود؛ بنابراین مدل بازگردانده‌شده وزن‌های مستقلی روی دستگاه جدید دارد. اگر لودر از این ویژگی پشتیبانی نکند، گره مدل را بدون تغییر با یک هشدار عبور می‌دهد.
- اگر گردش‌کار قبلاً دارای MultiGPU CFG Split باشد و GPU انتخاب‌شده با یکی از کلون‌های multigpu موجود مطابقت داشته باشد، آن کلون حذف می‌شود تا دو پچر به یک دستگاه متصل نشوند.
- قرار دادن این گره *بعد از* گره‌ای که قبلاً مدل را مصرف کرده است (مثلاً KSampler) توصیه نمی‌شود، زیرا اگر دستگاه با دستگاه اصلی مطابقت داشته باشد، هر تغییری که توسط گره قبلی اعمال شده است مشاهده خواهد شد.
