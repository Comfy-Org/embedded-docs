# 选择模型设备

SelectModelDevice 节点允许您选择扩散模型运行的设备（CPU 或特定 GPU）。根据所选选项，它会恢复加载器原有的设备、将模型固定到 CPU，或将其移动到特定 GPU，并自动处理与其他多 GPU 节点的冲突。

## 输入

| 参数 | 描述 | 数据类型 | 是否必填 | 范围 |
| --- | --- | --- | --- | --- |
| `model` | 要放置到特定设备上的扩散模型。 | MODEL | 是 |  |
| `device` | 模型的目標设备。选项根据可用 GPU 动态生成。（默认值：`"default"`） | COMBO | 是 | `"default"`<br>`"cpu"`<br>`"gpu:N"`，其中 N 为每个可用 GPU（例如 `"gpu:0"`、`"gpu:1"`、...） |

**参数详情：**
- `"default"`：恢复模型加载器分配的设备，即使之前的 SelectModelDevice 节点更改了该设备。
- `"cpu"`：将加载设备和卸载设备都固定到 CPU。
- `"gpu:N"`：将加载设备固定到第 N 个可用 GPU（例如，`"gpu:0"` 表示第一个 GPU）。卸载设备则恢复为加载器原有的选择。

**重要说明：**
- 未知的 `"gpu:N"` 值在验证时会被接受，这样可移植的工作流不会在 GPU 数量较少的机器上失败。在运行时，如果设备不可用，模型会原样传递，并记录一条日志消息。
- 如果当前机器上不存在请求的设备（例如，在具有 2 个 GPU 的机器上创建的工作流，在具有 1 个 GPU 的机器上打开），节点会原样传递模型并记录一条日志消息，而不是报错。
- 如果模型已在请求的设备上，节点会走快速路径，不会重新加载模型。
- 当请求的设备与当前设备不同时，会使用加载器的重新加载工厂创建一个新模型，因此返回的模型在新设备上具有独立的权重。不支持此功能的加载器会导致节点原样传递模型并发出警告。
- 如果工作流已应用 MultiGPU CFG Split，且所选 GPU 与现有的某个 multigpu 克隆相匹配，则该克隆会被移除，以避免两个 patcher 最终绑定到同一设备。
- 不建议将此节点放置在*已经使用过模型的节点*（例如 KSampler）之后，因为如果设备与原始设备匹配，先前节点更改的任何状态都会被观察到。

## 输出

| 输出名 | 描述 | 数据类型 |
| --- | --- | --- |
| `model` | 扩散模型，现已被放置到所选设备上。如果设备无效或不可用，模型将原样传递。 | MODEL |
