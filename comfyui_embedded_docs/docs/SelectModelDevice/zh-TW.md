# 選擇模型裝置

SelectModelDevice 節點可讓您選擇擴散模型運行的裝置（CPU 或特定的 GPU）。根據所選的選項，它會還原載入器的原始裝置、將模型固定到 CPU，或將其移至特定的 GPU，並自動處理與其他多 GPU 節點的衝突。

## 輸入

| 參數 | 說明 | 資料類型 | 必要 | 範圍 |
| --- | --- | --- | --- | --- |
| `model` | 要放置到特定裝置上的擴散模型。 | MODEL | 是 |  |
| `device` | 模型的目標裝置。選項會根據可用的 GPU 動態產生。（預設值："default"） | COMBO | 是 | `"default"`<br>`"cpu"`<br>`"gpu:N"`（每個可用的 GPU，例如 `"gpu:0"`、`"gpu:1"`、...） |

**參數詳細說明：**
- `"default"`：還原由模型載入器指定的裝置，即使先前的 SelectModelDevice 節點已變更它。
- `"cpu"`：將載入與卸載裝置都固定到 CPU。
- `"gpu:N"`：將載入裝置固定到第 N 個可用的 GPU（例如，`"gpu:0"` 表示第一個 GPU）。卸載裝置則還原為載入器的原始選擇。

**重要注意事項：**
- 未知的 `"gpu:N"` 值在驗證時會被接受，以便可攜式工作流程不會在 GPU 較少的機器上失敗。在執行時期，若裝置不存在，模型會原封不動地傳遞並記錄一則日誌訊息。
- 如果要求的裝置在目前機器上不存在（例如，在 2-GPU 機器上建立的工作流程在 1-GPU 機器上開啟），節點會原封不動地傳遞模型並記錄訊息，而不是失敗。
- 如果模型已在要求的裝置上，節點會採取快速路徑，不會重新載入模型。
- 當要求的裝置與目前裝置不同時，會使用載入器的重新載入工廠建立一個全新的模型，因此傳回的模型在新裝置上具有獨立的權重。不支援此功能的載入器會導致節點原封不動地傳遞模型並發出警告。
- 如果工作流程已套用 MultiGPU CFG Split，且所選的 GPU 與現有的多 GPU 複本之一相符，則該複本會被移除，以避免兩個修補程式最後繫結到相同的裝置。
- 不建議將此節點放置在已使用該模型的節點（例如 KSampler）*之後*，因為如果裝置與原始裝置相符，先前的節點所做的任何狀態變更都會被觀察到。
