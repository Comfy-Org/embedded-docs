# MiniMax H3: изображение в видео

Этот узел подготавливает conditioning и пустой latent, необходимые для генерации видео с помощью модели MiniMax H3. Он принимает текстовый запрос и, опционально, изображения для первого и/или последнего кадра видео и преобразует их во входные данные модели. Изображения ключевых кадров изменяются, кодируются и прикрепляются к conditioning в начале и конце видео.

## Входы

| Параметр | Описание | Тип данных | Обязательный | Диапазон |
|-----------|-------------|-----------|----------|-------|
| `clip` | Модель CLIP, используемая для токенизации запроса и кодирования изображений ключевых кадров в conditioning. | CLIP | Да |  |
| `vae` | Модель VAE, используемая для кодирования изображений ключевых кадров в латентное пространство, когда эти изображения предоставлены. | VAE | Да |  |
| `prompt` | Текстовый запрос, описывающий видео для генерации. Поддерживает многострочные и динамические запросы. | STRING | Да |  |
| `ширина` | Ширина видео в пикселях (по умолчанию: 1344). | INT | Да | 32 to MAX_RESOLUTION (step 32) |
| `высота` | Высота видео в пикселях (по умолчанию: 768). | INT | Да | 32 to MAX_RESOLUTION (step 32) |
| `длина` | Количество кадров при 24 fps, округляется вверх до ближайшего значения в сетке модели 17k+5 (124 ≈ 5 секунд; обученный диапазон — примерно 124–362, более длинные не тестировались) (по умолчанию: 124). | INT | Да | 5 до 3600 (step 17) |
| `первый_кадр` | Необязательное изображение, используемое в качестве первого кадра видео. Оно растягивается на весь размер холста, поэтому его соотношение сторон не сохраняется. Используется только первое изображение из входного пакета. | IMAGE | Нет |  |
| `последний_кадр` | Необязательное изображение, используемое в качестве последнего кадра видео. Оно кадрируется, чтобы покрыть весь холст, сохраняя соотношение сторон. Используется только первое изображение из входного пакета. | IMAGE | Нет |  |

Когда предоставлены `first_frame` и/или `last_frame`, изображения ключевых кадров кодируются с помощью VAE и прикрепляются к conditioning на кадре 0 и на последнем кадре соответственно. Когда не предоставлено ни одного из них, узел работает только на основе запроса. Запрошенный `length` округляется вверх до ближайшего допустимого количества кадров (17k + 5), поэтому фактическое количество кадров может быть немного больше запрошенного.

## Выходы

| Имя выхода | Описание | Тип данных |
|-------------|-------------|-----------|
| `позитивный` | Conditioning, содержащее закодированный запрос и, если предоставлены изображения ключевых кадров, закодированные ключевые кадры и количество кадров для модели MiniMax H3. | CONDITIONING |
| `latent` | Пустой аудио-видео latent, представляющий содержимое для генерации, с запрошенными шириной, высотой и количеством кадров. | LATENT |
