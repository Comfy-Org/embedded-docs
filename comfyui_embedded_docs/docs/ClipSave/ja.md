# CLIPを保存

`CLIPSave` ノードは、CLIPテキストエンコーダーモデルをSafeTensors形式でディスクに保存します。これは高度なモデルマージワークフロー向けに設計されており、モデルの内部構造に基づいてCLIPモデルをその構成要素（CLIP-L、CLIP-G、T5XXLなど）に自動的に分割し、各構成要素を個別のファイルとして保存します。

## 入力

| パラメータ | 説明 | データ型 | 必須 | 範囲 |
| --- | --- | --- | --- | --- |
| `clip` | 保存するCLIPモデル。 | CLIP | はい | - |
| `filename_prefix` | 保存ファイルのプレフィックスパスとファイル名です。ノードはコンポーネント接尾辞（例：`_clip_l`、`_clip_g`）とカウンターを追加して、一意のファイル名を作成します（デフォルト：`clip/ComfyUI`）。 | STRING | はい | - |
| `prompt` | ワークフローのプロンプト情報で、出力ファイルにメタデータとして保存されます。このパラメータはUIでは非表示です。 | PROMPT | いいえ | - |
| `extra_pnginfo` | 追加のメタデータで、出力ファイルにキーと値のペアとして保存されます。このパラメータはUIでは非表示です。 | EXTRA_PNGINFO | いいえ | - |

## 出力

このノードには出力接続はありません。処理されたファイルは `ComfyUI/output/` ディレクトリに直接保存されます。

### 保存ファイルの詳細

このノードはCLIPモデルの状態辞書（state dictionary）を解析し、検出された各コンポーネントについて個別のSafeTensorsファイルを保存します。コンポーネントはパラメータキーのプレフィックスによって識別されます。ノードは以下のプレフィックスを順番にチェックします：

- `clip_l.` (CLIP-L テキストエンコーダー)
- `clip_g.` (CLIP-G テキストエンコーダー)
- `clip_h.` (CLIP-H テキストエンコーダー)
- `t5xxl.` (T5-XXL テキストエンコーダー)
- `pile_t5xl.` (Pile-T5-XL テキストエンコーダー)
- `mt5xl.` (mT5-XL テキストエンコーダー)
- `umt5xxl.` (UMT5-XXL テキストエンコーダー)
- `t5base.` (T5-Base テキストエンコーダー)
- `gemma2_2b.` (Gemma 2 2B テキストエンコーダー)
- `llama.` (LLaMA テキストエンコーダー)
- `hydit_clip.` (Hydit CLIP テキストエンコーダー)
- 空のプレフィックス（その他のCLIPコンポーネント）

検出された各コンポーネントについて、ノードは `{filename}_{counter:05}_.safetensors` という名前のファイルを作成します（例：`ComfyUI_clip_l_00001_.safetensors`）。このとき、コンポーネント名はファイル名プレフィックスに追加され、カウンターによって一意のファイル名が保証されます。コンポーネントを保存する際、そのパラメータキーから `transformer.` プレフィックスが削除されます。

各ファイルに書き込まれるメタデータには、ワークフローのプロンプトと追加のPNG情報が含まれます。ただし、`--disable-metadata` コマンドライン引数でメタデータの保存が無効になっている場合は除きます。
