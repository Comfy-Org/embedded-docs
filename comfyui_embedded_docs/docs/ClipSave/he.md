# ClipSave

הצומת `CLIPSave` שומר מודל מקודד טקסט CLIP לדיסק בפורמט SafeTensors. הוא מיועד לתהליכי מיזוג מודלים מתקדמים, ומפצל אוטומטית את מודל ה-CLIP לרכיביו (כגון CLIP-L, CLIP-G או T5XXL) בהתבסס על המבנה הפנימי של המודל, ושומר כל רכיב בקובץ נפרד.

## קלטים

| פרמטר | תיאור | סוג נתונים | נדרש | טווח |
| --- | --- | --- | --- | --- |
| `clip` | מודל ה-CLIP שיש לשמור. | CLIP | כן | - |
| `filename_prefix` | נתיב הקידומת ושם הקובץ עבור הקובץ/קבצים הנשמרים. הצומת יוסיף סיומת רכיב (לדוגמה, `_clip_l`, `_clip_g`) ומונה כדי ליצור שמות קבצים ייחודיים (ברירת מחדל: `clip/ComfyUI`). | STRING | כן | - |
| `prompt` | מידע הפרומפט של זרימת העבודה, נשמר כמטא-נתונים בקובץ הפלט. פרמטר זה מוסתר בממשק המשתמש. | PROMPT | לא | - |
| `extra_pnginfo` | מטא-נתונים נוספים, נשמרים כצמדי מפתח-ערך בקובץ הפלט. פרמטר זה מוסתר בממשק המשתמש. | EXTRA_PNGINFO | לא | - |

## פלטים

לצומת זה אין חיבורי פלט. הוא שומר את הקבצים המעובדים ישירות לספריית `ComfyUI/output/`. הקבצים הנשמרים כוללים מטא-נתונים (הפורמט מוגדר כ-"pt", בתוספת פרומפט זרימת העבודה וכל מידע PNG נוסף) אלא אם ComfyUI מופעל עם הארגומנט `--disable-metadata`.

### פרטי הקבצים הנשמרים

הצומת מנתח את מילון המצב של מודל ה-CLIP ושומר קובצי SafeTensors נפרדים עבור כל רכיב שזוהה. הרכיב מזוהה לפי הקידומת של מפתחות הפרמטרים שלו. הקידומות הבאות נבדקות:

- `clip_l.` (מקודד טקסט CLIP-L)
- `clip_g.` (מקודד טקסט CLIP-G)
- `clip_h.` (מקודד טקסט CLIP-H)
- `t5xxl.` (מקודד טקסט T5-XXL)
- `pile_t5xl.` (מקודד טקסט Pile-T5-XL)
- `mt5xl.` (מקודד טקסט mT5-XL)
- `umt5xxl.` (מקודד טקסט UMT5-XXL)
- `t5base.` (מקודד טקסט T5-Base)
- `gemma2_2b.` (מקודד טקסט Gemma 2 2B)
- `llama.` (מקודד טקסט LLaMA)
- `hydit_clip.` (מקודד טקסט Hydit CLIP)
- קידומת ריקה (רכיבי CLIP אחרים)

עבור כל רכיב שזוהה, הצומת יוצר קובץ בשם `{filename_prefix}_{counter:05}_.safetensors`, כאשר קידומת הרכיב מתווספת לקידומת שם הקובץ (לדוגמה, `clip/ComfyUI_clip_l_00001_.safetensors`). הקידומת `transformer.` מוסרת ממפתחות הפרמטרים בזמן השמירה.
