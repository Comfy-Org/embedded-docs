# CLIPTextEncodeHiDream

Узел CLIPTextEncodeHiDream обрабатывает четыре отдельных текстовых входа с использованием различных языковых моделей (CLIP-L, CLIP-G, T5-XXL и LLaMA) и объединяет их в единый выход conditioning. Он токенизирует каждый текстовый вход соответствующей моделью и кодирует их вместе с помощью подхода запланированного кодирования, что обеспечивает более сложное текстовое conditioning за счёт одновременного использования нескольких языковых моделей.

## Входы

| Параметр | Описание | Тип данных | Обязательный | Диапазон |
| --- | --- | --- | --- | --- |
| `clip` | Модель CLIP, используемая для токенизации и кодирования | CLIP | Да | - |
| `clip_l` | Текстовый вход для обработки моделью CLIP-L. Поддерживает многострочный текст и динамические промпты. | STRING | Да | - |
| `clip_g` | Текстовый вход для обработки моделью CLIP-G. Поддерживает многострочный текст и динамические промпты. | STRING | Да | - |
| `t5xxl` | Текстовый вход для обработки моделью T5-XXL. Поддерживает многострочный текст и динамические промпты. | STRING | Да | - |
| `llama` | Текстовый вход для обработки моделью LLaMA. Поддерживает многострочный текст и динамические промпты. | STRING | Да | - |

**Примечание:** Все четыре текстовых входа (`clip_l`, `clip_g`, `t5xxl` и `llama`) обязательны для корректной работы, поскольку каждый из них вносит вклад в итоговый выход conditioning через процесс запланированного кодирования.

## Выходы

| Имя выхода | Описание | Тип данных |
| --- | --- | --- |
| `CONDITIONING` | Совокупный выход conditioning из всех обработанных текстовых входов, закодированный с использованием метода запланированного кодирования | CONDITIONING |
