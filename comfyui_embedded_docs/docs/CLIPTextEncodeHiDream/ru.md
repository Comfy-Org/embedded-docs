# CLIPTextEncodeHiDream

Узел CLIPTextEncodeHiDream обрабатывает четыре отдельных текстовых входа с использованием разных языковых моделей (CLIP-L, CLIP-G, T5-XXL и LLaMA) и объединяет их в единый выходной conditioning. Каждый текстовый вход токенизируется соответствующей моделью, после чего все они кодируются вместе с помощью метода запланированного кодирования. Это обеспечивает более сложную текстовую обусловленность за счёт одновременного использования нескольких языковых моделей.

## Входы

| Параметр | Описание | Тип данных | Обязательный | Диапазон |
| --- | --- | --- | --- | --- |
| `clip` | Модель CLIP, используемая для токенизации и кодирования | CLIP | Да | - |
| `clip_l` | Текстовый ввод для обработки моделью CLIP-L. Поддерживает многострочный текст и динамические промпты. | STRING | Да | - |
| `clip_g` | Текстовый ввод для обработки моделью CLIP-G. Поддерживает многострочный текст и динамические промпты. | STRING | Да | - |
| `t5xxl` | Текстовый ввод для обработки моделью T5-XXL. Поддерживает многострочный текст и динамические промпты. | STRING | Да | - |
| `llama` | Текстовый ввод для обработки моделью LLaMA. Поддерживает многострочный текст и динамические промпты. | STRING | Да | - |

**Примечание:** Все четыре текстовых ввода (`clip_l`, `clip_g`, `t5xxl` и `llama`) обязательны для корректной работы, поскольку каждый из них вносит вклад в итоговый выходной conditioning через процесс запланированного кодирования.

## Выходы

| Имя выхода | Описание | Тип данных |
| --- | --- | --- |
| `CONDITIONING` | Объединённый выходной conditioning, полученный из всех обработанных текстовых вводов и закодированный с помощью метода запланированного кодирования | CONDITIONING |
