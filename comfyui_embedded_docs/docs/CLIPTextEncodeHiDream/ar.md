# ترميز نص CLIP لـ HiDream

```markdown
تقوم عقدة CLIPTextEncodeHiDream بمعالجة أربعة مدخلات نصية منفصلة باستخدام نماذج لغة مختلفة (CLIP-L وCLIP-G وT5-XXL وLLaMA) وتجمعها في مخرج تكييف واحد. تقوم بتقطيع كل مدخل نصي مع النموذج المقابل له وتشفيرها معًا باستخدام نهج تشفير مجدول، مما يتيح تحكمًا نصيًا أكثر تطورًا من خلال الاستفادة من نماذج لغة متعددة في وقت واحد.

## المدخلات

| المعامل | الوصف | نوع البيانات | مطلوب | النطاق |
| --- | --- | --- | --- | --- |
| `CLIP` | نموذج CLIP المستخدم في التقطيع إلى رموز والتشفير | CLIP | نعم | - |
| `CLIP-L` | مدخل نصي لمعالجة نموذج CLIP-L. يدعم النصوص متعددة الأسطر والموجهات الديناميكية. | STRING | نعم | - |
| `CLIP-G` | مدخل نصي لمعالجة نموذج CLIP-G. يدعم النصوص متعددة الأسطر والموجهات الديناميكية. | STRING | نعم | - |
| `T5-XXL` | مدخل نصي لمعالجة نموذج T5-XXL. يدعم النصوص متعددة الأسطر والموجهات الديناميكية. | STRING | نعم | - |
| `LLaMA` | مدخل نصي لمعالجة نموذج LLaMA. يدعم النصوص متعددة الأسطر والموجهات الديناميكية. | STRING | نعم | - |

**ملاحظة:** جميع المدخلات النصية الأربعة (`clip_l`، `clip_g`، `t5xxl`، و`llama`) مطلوبة لضمان العمل السليم، حيث يساهم كل منها في مخرج التكييف النهائي من خلال عملية التشفير المجدولة.

## المخرجات

| اسم المخرج | الوصف | نوع البيانات |
| --- | --- | --- |
| `CONDITIONING` | مخرج التكييف المجمع من جميع المدخلات النصية المعالجة، والمشفر باستخدام طريقة التشفير المجدولة | CONDITIONING |
```
