# ترميز نص CLIP لـ HiDream

تتولّى عقدة CLIPTextEncodeHiDream معالجة أربعة مدخلات نصية منفصلة باستخدام نماذج لغوية مختلفة (CLIP-L وCLIP-G وT5-XXL وLLaMA) وتجمعها في مخرج تكييف واحد. وهي تقوم بتقطيع كل مدخل نصي باستخدام النموذج المقابل له وتشفيرها معًا باستخدام نهج الترميز المُجدول، مما يتيح تكييفًا نصيًا أكثر تطورًا من خلال الاستفادة من نماذج لغوية متعددة في وقت واحد.

## المدخلات

| المعامل | الوصف | نوع البيانات | مطلوب | النطاق |
| --- | --- | --- | --- | --- |
| `clip` | نموذج CLIP المستخدم في التقطيع والترميز | CLIP | نعم | - |
| `clip_l` | مدخل نصي لمعالجة نموذج CLIP-L. يدعم النص متعدد الأسطر والبرومبتات الديناميكية. | STRING | نعم | - |
| `clip_g` | مدخل نصي لمعالجة نموذج CLIP-G. يدعم النص متعدد الأسطر والبرومبتات الديناميكية. | STRING | نعم | - |
| `t5xxl` | مدخل نصي لمعالجة نموذج T5-XXL. يدعم النص متعدد الأسطر والبرومبتات الديناميكية. | STRING | نعم | - |
| `llama` | مدخل نصي لمعالجة نموذج LLaMA. يدعم النص متعدد الأسطر والبرومبتات الديناميكية. | STRING | نعم | - |

**ملاحظة:** جميع المدخلات النصية الأربعة (`clip_l` و`clip_g` و`t5xxl` و`llama`) مطلوبة لضمان الأداء السليم، حيث يساهم كل منها في مخرج التكييف النهائي من خلال عملية الترميز المُجدول.

## المخرجات

| اسم المخرج | الوصف | نوع البيانات |
| --- | --- | --- |
| `CONDITIONING` | مخرج التكييف المدمج من جميع المدخلات النصية المعالجة، والمشفّر باستخدام أسلوب الترميز المُجدول | CONDITIONING |
