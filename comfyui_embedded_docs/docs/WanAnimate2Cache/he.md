# WanAnimate2Cache

מבצע מטמון של האקטיבציות לכל בלוק של וידאו התנוחה פעם אחת, כך שאין צורך לחשב אותן מחדש בכל שלב דגימה, מה שמקצר את זמן היצירה בכחצי. המחיר הוא שימוש נוסף בזיכרון: כ-12.5 GB של זיכרון RAM של המערכת ברזולוציית 480x832 עם 81 פריימים ב-bf16, כאשר הצריכה עולה עם הרזולוציה ואורך הווידאו.

## קלטים

| פרמטר | תיאור | סוג נתונים | נדרש | טווח |
|-----------|-------------|-----------|----------|-------|
| `model` | מודל ה-Wan Animate2 שאליו יש לצרף את המטמון. | MODEL | כן | |
| `device` | היכן לשמור את המטמון. cpu (RAM) היא הבחירה הבטוחה; המטמון לא ייכנס ל-VRAM לצד המודל בגדלים אופייניים. gpu (VRAM) יכול להיות מהיר יותר אם הוא נכנס. (ברירת מחדל: "cpu") | STRING | כן | "cpu"<br>"gpu" |
| `dtype` | דיוק אחסון. default שומר את האקטיבציות בסוג הנתונים לחישוב של המודל. int8 מצמצם את המטמון בחצי, int4 מצמצם אותו לרבע, convrot משמש לשמירה על הדיוק. (ברירת מחדל: "default") | STRING | כן | "default"<br>"int8"<br>"int4" |

הערה: כאשר משתמשים בחלונות הקשר (context windows), כל חלון נשמר במטמון בנפרד, כך ששימוש הזיכרון עולה עם מספר החלונות. יש להשתמש בלוח הזמנים static_standard, מכיוון שלוחות זמנים uniform מזיזים את החלונות בכל שלב והמטמון לא נעשה בו שימוש חוזר.
