# WanAnimate2Cache

يقوم بتخزين التنشيطات لكل كتلة في فيديو الوضعية (pose-video) مرة واحدة بحيث لا يلزم إعادة حسابها في كل خطوة من خطوات أخذ العينات، مما يقلل وقت التوليد إلى النصف تقريبًا. المقابل هو زيادة استخدام الذاكرة: حوالي 12.5 جيجابايت من ذاكرة الوصول العشوائي للنظام بدقة 480x832 مع 81 إطارًا بصيغة bf16، وتزداد هذه الكمية مع زيادة الدقة وطول الفيديو.

## المدخلات

| المعامل | الوصف | نوع البيانات | مطلوب | النطاق |
|---------|-------|--------------|-------|--------|
| `model` | نموذج Wan Animate2 الذي سيتم إرفاق الكاش به. | MODEL | نعم | |
| `device` | أين يتم الاحتفاظ بالكاش. الخيار cpu (ذاكرة الوصول العشوائي) هو الاختيار الآمن، إذ لن يتسع الكاش في ذاكرة الفيديو (VRAM) إلى جانب النموذج بالأحجام النموذجية. الخيار gpu (ذاكرة الفيديو) قد يكون أسرع إذا كان مناسبًا. (الافتراضي: "cpu") | STRING | نعم | "cpu"<br>"gpu" |
| `dtype` | دقة التخزين. الوضع الافتراضي يخزّن التنشيطات بنفس دقة الحساب للنموذج. int8 يقلص الكاش إلى النصف، وint4 يقلصه إلى الربع، ويُستخدم convrot للحفاظ على الدقة. (الافتراضي: "default") | STRING | نعم | "default"<br>"int8"<br>"int4" |

ملاحظة: عند استخدام نوافذ السياق (context windows)، يتم تخزين كل نافذة على حدة، لذا يزداد استخدام الذاكرة مع عدد النوافذ. يجب استخدام جدول static_standard، لأن الجداول الموحدة تُحدث إزاحة للنوافذ في كل خطوة وبالتالي لا يُعاد استخدام الكاش.
