# SaveGLB

Узел SaveGLB сохраняет данные 3D-сетки или входные 3D-файлы в выходной каталог. Он принимает данные сетки и распространённые форматы 3D-файлов (GLB, GLTF, OBJ, FBX, STL, USDZ, PLY, SPLAT, SPZ, KSPLAT) и экспортирует их с указанным префиксом имени файла. Входные данные сетки записываются в виде файлов GLB (по одному на элемент пакета), а входные 3D-файлы сохраняются в исходном формате.

## Входы

| Параметр | Описание | Тип данных | Обязательный | Диапазон |
|----------|----------|------------|--------------|----------|
| `сетка` | Сетка или 3D-файл для сохранения | MESH or FILE3D | Да | Mesh data<br>GLB<br>GLTF<br>OBJ<br>FBX<br>STL<br>USDZ<br>PLY<br>SPLAT<br>SPZ<br>KSPLAT<br>Any splat format<br>Any point cloud format<br>Any 3D file format |
| `префикс_имени_файла` | Префикс для имени выходного файла (по умолчанию: "3d/ComfyUI"). Префикс может содержать путь к вложенной папке, поэтому по умолчанию файлы сохраняются во вложенной папке "3d" выходного каталога | STRING | Нет | - |

Примечание: Если входной параметр `mesh` является 3D-файлом, узел сохраняет его с исходным расширением формата (если у файла нет формата, используется GLB). Если это данные сетки, каждый элемент пакета сохраняется как отдельный файл `.glb`; пустые элементы (без вершин или граней) пропускаются с предупреждением. Имена выходных файлов следуют шаблону `{filename_prefix}_{counter:05}_.{ext}` с увеличивающимся счётчиком. Метаданные рабочего процесса (prompt и дополнительная информация PNG) встраиваются в сохраняемые файлы, если метаданные включены.

## Выходы

| Имя выхода | Описание | Тип данных |
|------------|----------|------------|
| `ui` | Отображает сохранённые 3D-файлы в пользовательском интерфейсе с информацией об имени файла, вложенной папке и типе | UI |
