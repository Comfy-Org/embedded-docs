# ترميز نص CLIP لـ SD3

CLIPTextEncodeSD3 يعالج مدخلات النص لنماذج Stable Diffusion 3 عن طريق ترميز مطالبات نصية متعددة باستخدام نماذج CLIP مختلفة. يتعامل مع ثلاثة مدخلات نصية منفصلة (`clip_g` و`clip_l` و`t5xxl`) ويوفر خيارات لإدارة حشو النص الفارغ. تضمن العقدة محاذاة صحيحة للرموز بين المدخلات النصية المختلفة وتُرجع بيانات تكييف (conditioning) مناسبة لخطوط إنتاج SD3.

## المدخلات

| المعامل | الوصف | نوع البيانات | مطلوب | النطاق |
| --- | --- | --- | --- | --- |
| `CLIP` | نموذج CLIP المستخدم لترميز النص | CLIP | نعم | - |
| `CLIP-L` | مدخل نصي لنموذج CLIP المحلي. يدعم النص متعدد الأسطر والمطالبات الديناميكية. | STRING | نعم | - |
| `CLIP-G` | مدخل نصي لنموذج CLIP العام. يدعم النص متعدد الأسطر والمطالبات الديناميكية. | STRING | نعم | - |
| `T5-XXL` | مدخل نصي لنموذج T5-XXL. يدعم النص متعدد الأسطر والمطالبات الديناميكية. | STRING | نعم | - |
| `حشو فارغ` | يتحكم في كيفية التعامل مع مدخلات النص الفارغة. عند التعيين على "none"، تؤدي المدخلات النصية الفارغة لـ `clip_g` أو `clip_l` أو `t5xxl` إلى قوائم رموز فارغة بدلاً من الحشو. عند التعيين على "empty_prompt"، يتم تحويل المدخلات الفارغة إلى رموز كمطالبات فارغة (سلوك الحشو القياسي). هذه معلمة متقدمة (الافتراضي: "none"). | COMBO | نعم | `"none"`<br>`"empty_prompt"` |

**قيود المعاملات:**

- عند تعيين `empty_padding` على "none"، تؤدي المدخلات النصية الفارغة لـ `clip_g` أو `clip_l` أو `t5xxl` إلى قوائم رموز فارغة بدلاً من الحشو
- توازن العقدة تلقائيًا أطوال الرموز بين مدخلي `clip_l` و`clip_g` عن طريق حشو الأقصر برموز فارغة عندما تختلف الأطوال
- تدعم جميع المدخلات النصية المطالبات الديناميكية وإدخال النص متعدد الأسطر
