# מטמון Qwen Image 2.1

הצומת QwenImage21Cache מגדיר את מטמון קידומת ה-KV של מודל Qwen-Image 2.1: היכן נשמרים המפתחות והערכים השמורים ובאיזו דיוק. אסימוני טקסט ואסימוני רפרנס מחושבים פעם אחת ונעשה בהם שימוש חוזר לאורך שלבי הדגימה, ומכאן מגיע עיקר השיפור במהירות בתהליכי עבודה של עריכה, והצומת הזה מאפשר להחליף זיכרון במהירות או לשלול את המטמון לחלוטין. צומת זה מסומן כניסיוני.

## קלטים

| פרמטר | תיאור | סוג נתונים | חובה | טווח |
| --- | --- | --- | --- | --- |
| `model` | מודל Qwen-Image 2.1 שעבורו מוגדר מטמון הקידומת. | MODEL | כן | - |
| `device` | היכן נשמרים המפתחות והערכים השמורים. `"auto"` (ברירת מחדל) משתמש תחילה ב-VRAM פנוי ואחר כך ב-RAM; `"gpu"` שומר את המטמון ב-VRAM; `"cpu"` שומר אותו ב-RAM ומבצע prefetch מאחורי החישוב, מה שמשפיע מעט על המהירות; `"off"` מחשב מחדש את הקידומת בכל שלב, מה שאיטי יותר, אך זו הדרך היחידה לשלול את המטמון. | COMBO | כן | `"auto"`<br>`"gpu"`<br>`"cpu"`<br>`"off"` |
| `dtype` | דיוק האחסון של המטמון. `"default"` הוא ללא אובדן; `"int8"` מחצה את גודל המטמון בדיוק של בערך bf16; `"int4"` מרבע אותו אך בערך מכפיל את השגיאה לכל שלב. | COMBO | כן | `"default"`<br>`"int8"`<br>`"int4"` |

כאשר המטמון אינו נכנס לזיכרון, המודל מחשב מחדש את הקידומת במקום לפנות את המשבצת של הענף האחר, כך שהגדרה גדולה מדי פוגעת במהירות במקום להכשיל את ההרצה.
